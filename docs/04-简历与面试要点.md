# Agent 项目简历与面试要点

## 可使用的项目描述

**AudioRAG：基于自研 ReAct 运行时的多 Agent 音频学习系统｜个人项目**

技术栈：Java 17、Spring Boot、原生 Function Calling、MySQL/JPA、Redis、MinIO、Qdrant、ONNX Runtime、SSE、Electron/Vue。

- 自研模型决策—工具调用—观察反馈循环，接入原生 Function Calling，完成流式工具参数聚合、调用编号回传与输出校验；通过共享预算、重复动作检测和有限修正控制循环执行。
- 实现 Supervisor 与学习规划、资料研究、课程编写、内容复核四类专业 Agent；为子 Agent 隔离上下文和工具权限，通过可追溯产物编号组织任务协作。
- 设计分层上下文管理，基于同会话原始历史与可追溯检查点，支持近期窗口、历史BM25召回、原文摘记及混合策略；使用turn_id维护轮次、原文范围和哈希核对记忆来源，结合结构化工具观察压缩、按需重读与任务状态恢复，通过多预算对照实验验证重要信息保留及协议完整性。
- 设计带文档版本、原文坐标和片段顺序的共享RAG索引，支持模型通过Function Calling选择BM25/向量/RRF混合召回及Top-K/邻居/RSE证据组合；以本地ONNX模型开展切片、召回与上下文预算消融实验，记录证据覆盖、密度和延迟，而非仅按文档命中判断效果。
- 实现任务与产物持久化、人工确认及幂等执行，保存调用轨迹并标记中断任务；用户确认后应用学习计划或合成本机音频，通过回归测试验证协议、权限和状态流转。

## 面试时应能解释

完整的模拟面试、连续追问、据实回答与改进清单见[项目模拟面试：30组问答与审查](09-项目模拟面试问答与审查.md)。模拟回答不等于用户已掌握，需按文末自测独立演练。

1. ReAct 循环的入口和退出条件在哪里？为什么不能只靠模型返回“完成”？
2. 为什么必须保留 assistant.tool_calls 与所有 tool_call_id 的配对？
3. 主控和子 Agent 用相同模型时，为什么仍可称多 Agent？各自的上下文、工具权限和输出契约有什么不同？
4. 滑动窗口和本轮工具观察压缩如何分工？如何避免裁剪后破坏协议？
5. 老产物引用编号为什么需要重映射？来源如何追溯？
6. 模型失败后哪些记录保留，哪些动作不会自动重放？
7. 为什么计划和音频需要确认？如何防止重复点击造成重复执行？
8. 测试模型与真实模型评测有什么区别？契约通过率为何不等于答案正确率？

当前不写未实现的技术：Spring AI、LangGraph 框架、并行子 Agent 调度、自动证明事实正确、生产级高并发和未经实测的准确率/性能提升。真实模型效果应通过项目内验收任务和人工审阅补充数据。
