# 跨语言与体裁改稿修复

日期：2026-10-24。用户反馈：对英文或双语跟读讲稿提出“在当前讲稿的基础上修改全篇为中文的中国散文”，助手反复被语言校验拒绝，继而保留英文、逐段试改或另建草稿。

## 原因

`ContinuousAudioService` 的单段修改、整篇重写和续写都要求新旧正文检测语言相同；`ScriptReviser` 同时提示保持原语言、禁止翻译，并把所有文体限制为口语讲述。用户明确指定新的语言和体裁也不能覆盖这些旧规则。单段改稿又按原始字符数强制 0.5—2 倍，英文转换为中文时容易被误判。

此前测试覆盖了同语言改稿、并发与确认边界，缺少“已有英文十段按明确指令整体改成中文散文”的服务及 HTTP 回归。这次补齐，不能用旧测试全通过推断这项产品行为已经验证。

## 行为

- 明确要求改为中文、英文或双语时，按本次目标语言校验；未要求换语言时沿用原稿语言，继续拒绝模型意外换语言。
- 提示词遵守用户指定的散文、故事等文体。全篇改中文散文时，不再保留英文跟读或译文教学格式，也不靠夹英文规避校验。
- 用户主动提供的手工正文可以更换语言。模型翻译、跨语言改写或明确缩短/扩写，不再受同语言字符数倍率限制；绝对长度上限保留。
- 整篇改写仍进入同一音频队列的红绿差异审核。确认前不改正文、不合成；确认后只按需合成首个受影响片段，仍可撤回。
- 确认前检查实际正文与音色兼容性，不支持时保留原稿与待审版本。默认沿用当前音色，也可以在差异确认处改选音色或自动选择，与正文一并确认生效。
- 确认后按实际全文更新语言元数据，标记正文已编辑，并清除逐字原文状态，避免后续“继续”重新回到旧语言或误续读原文。

本次反馈的 `clone-mvjppvkn` 经本地音色清单核实支持中文和英文，无需为改中文而更换声音。未擅自应用用户现有队列或处理其待确认草稿。
