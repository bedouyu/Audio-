## 对照方法与边界

人工20场景，每个16完整轮，固定dev10/test10，四策略×1000/3000/6000序列化JSON字符预算，共240条件。每种策略独立从同样历史、原文摘记与query组装，gold不进入策略。原文摘记是启发式摘录，不是模型生成摘要。

本地运行目录：`.cache/memory-experiments/diagnostic-v1-20261009-final/`。完整片段、快照及参数在report.json，逐题results.csv，汇总summary.csv。以下是独立gold的完整重要引句进入上下文的比例，不是模型回答正确率或企业业务成功率。

## 不能只看覆盖率

仅2个test场景含明确的旧要求标签。其中，query_recall/hybrid的平均旧要求暴露为50%，extractive_notes为25%，recent_window为0%。暴露包括部分原文出现在上下文，不等于模型已经采纳旧要求；数据里也可能需要同时看到原要求与更正，才能理解变化。

因此不能以覆盖率最高就宣称“自动选出最佳memory”。当前请求与较晚更正优先，来源保留时序，模型可分段重读；真实约束遵守、过时要求采纳和任务完成仍需回答级测试。

所有240组合均满足真实JSON预算与原文片段真实性检查。foreign fixture未被传入策略产生的0暴露不是数据库隔离证明；另有真实H2 session/user/project隔离测试。角色不被改写也不等于模型能抵抗所有提示注入。

## 工具观察回放

同一脚本还运行8个固定协议回放场景×preview/structured，共16条件。原文正文与引用故意分离，比较结构引用/产物/source ID保留、原status、JSON有效性、工具调用配对和最新轮完整性。报告用tool-compaction-前缀，不覆盖历史实验。

这些是合成协议轨迹，不表示工具真正调用成功或模型答对。最新轮过大时的LIMIT是预期安全停止；无返回上下文时指标为空，不能当压缩成功。详细实测见tool-compaction-summary.csv与逐场景JSON。

7个可返回上下文的场景中，structured保留了6/6产物、5/5引用与11/11原文source结构标识及原status；preview只保留原始前缀，没有保留这些结构标识。两者均保留工具协议与最新轮，另外1场景均显式LIMIT。输入故意把引用放在大正文之后，属于验证此失效模式的回放，不代表所有工具输出上100%引用保留。

## 真实模型引用恢复

显式运行`./run-memory-experiments.ps1 -RunModelEvaluation -MaxModelCalls 8`才会调用环境中配置的模型，可能计费。请求不给gold或未选完整历史，客观核对返回引用是否由可见片段支持、是否恢复重要原句；不是模型自评分，也不是完整课程或自由回答质量评测。

如果未运行这个付费选项，本目录没有真实模型成绩，不能把本地覆盖率写成DeepSeek准确率提升。后续需增加真实长会话，按会话/任务分组留出测试，冻结模型和总预算，再选择成本与效果合适的配置。
