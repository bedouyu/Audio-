# Agent 可靠性升级记录

日期：2026-10-09。项目：`AI音频/audiorag-java`。

本轮针对[模拟面试审查](09-项目模拟面试问答与审查.md)发现的软件契约问题升级，优先修复完成判定、复核绑定、重复请求、确认竞态与流式取消。原问答保留为升级前的审查快照，不应再用其中旧实现描述当前代码。

## 2. 最低任务规格

`TaskSpecification` 与模型最后一句“完成了”独立。支持四类产物：LEARNING_PLAN、RESEARCH_REPORT、SCRIPT_DRAFT、REVIEW_REPORT。

入口先提取明确生成命令的最低要求。例如：

- “生成讲稿，不要公式”仍要求 SCRIPT_DRAFT。
- “生成讲稿，告诉我怎么学”不会因为后半句是问题而跳过讲稿。
- “如何生成讲稿”是问答，不强制生成。
- “生成学习计划但不要生成讲稿”只要求 LEARNING_PLAN。

开放式目标可以通过 `declare_task_specification` 补充要求。模型只能增加，不能删掉用户明确要求；首次声明或首次委派后冻结规格，数据库拒绝变更。失败任务也尽量保留规格用于核查。直接问答仍可不委派。

API 可显式传 `required_artifacts`。这是最低产物契约，**不是自然语言语义的完整证明**：没有实现对所有开放目标自动证明“完整覆盖所有课程/质量要求”。同一运行必须产生要求的产物，不能把一段完成声明当作文件或报告。

核心入口：`core/guard/TaskSpecification*`、`tools/agent/DeclareTaskSpecificationTool`、`core/loop/ReActLoopEngine`。

## 3. 同一版本的读取、检查与复核

产物阅读工具会返回原始 `content_hash` 和渲染后的哈希，并按实际返回正文登记阅读区间。引用编号重映射可能改变渲染文本，因此不能混用两个哈希。长讲稿需要分页读完后才能批准。

复核 JSON 的契约：

```json
{
  "reviewed_artifact_id": "实际讲稿产物编号",
  "content_hash": "该讲稿原始内容的64位SHA-256",
  "approved": true,
  "issues": [],
  "reason": "已核对的内容和仍存在的边界"
}
```

批准要求：目标属于传入白名单、是实际讲稿、已完整阅读同一渲染版本、本机检查针对同一原始/渲染版本且通过、问题列表为空。只检查另一个产物、读取局部、使用旧哈希，都不能获批。本机检查不会把其他产物碰巧相同的 E1 当作本讲稿的原始来源。

这只能增强来源与版本一致性；**不等于证明事实正确、数学正确或模型复核一定可靠**。

## 4. 请求幂等与确认审计

聊天 API 接受可选 `request_id`，格式为 UUID。桌面端每次新发送自动生成一个。

- 同用户、同项目、同编号、相同请求：已完成/待确认任务直接返回原回答及最新产物状态，不再次调用模型。
- 同编号改变消息、原 session 参数、Memory 策略或产物要求：409。
- RUNNING、FAILED、INTERRUPTED、CANCELLED、LIMIT_REACHED：409，并提示查询原任务或使用新编号；不自动重跑。
- 未提供编号的旧客户端保持兼容，但不获得聊天请求幂等保障。
- 幂等针对**同一个请求编号**，不是“内容相似”或“再次点击发送”；新请求仍是新任务。

指纹不把显式空产物要求与未提供要求混为同一请求。首次请求没有 session_id，重放也能返回服务端原先建立的 session_id。

计划应用与讲稿合成现在都要求 `expected_content_hash`。讲稿合成默认还需 `review_id`；如人工决定覆盖审核，须明确 `override_review=true` 和 10—500 字理由。界面会单独提示，不能默认略过审核。

审计记录包含操作、用户、确认标记、内容哈希、产物版本、时间、审核绑定或覆盖理由。任务仍在模型运行中时不允许执行草稿。READY/APPLIED 的重复确认只复用已有结果；旧客户端不带哈希仅能复用已完成结果，不能开始新执行。

这不是跨实例、跨 TTS/数据库/文件的 exactly-once：当前会话锁主要针对单进程，数据库唯一键是额外保护。

## 5. 音频崩溃窗口的处理

音频状态：DRAFT → GENERATING → READY；进程中断或合成异常会进入 NEEDS_REVIEW。

在 NEEDS_REVIEW 下，界面提供两种明确操作：

1. 核验原音频并恢复。服务端先核对所有权、内容哈希、状态、原音频编号和地址，再读取该 WAV。验证 RIFF 长度、fmt/data 结构与数据对齐等；成功后补记结果，**不调用 TTS**。
2. 人工重置合成尝试。绑定旧编号和哈希、填写理由，保留旧编号/地址审计后回到 DRAFT；**不删除旧文件，也不立即调用 TTS**。之后需要另外确认审核和合成，才创建新编号。

只支持 PCM、IEEE float、Extensible WAV，不支持 RF64 或压缩 WAV。重置后旧尝试的失败回调不能把新尝试标成中断。失败/中断的模型任务，即使其有效草稿后来被人工执行，也不会伪装成模型任务成功。

恢复接口：

- POST `/api/v1/projects/{projectId}/agent/artifacts/{id}/recover-synthesis`
- POST `/api/v1/projects/{projectId}/agent/artifacts/{id}/retry-synthesis`

核心入口：`AgentArtifactApprovalService`、`AgentArtifactStore`、`WavVerifier`。

## 6. 检索错误与流式协议

向量检索先读取已有 collection 的维度并检查查询/上传向量长度；不自动新建、删除或重建 collection。指定新版文档的 BM25 分支不再额外访问向量服务。

暂时网络故障且有新版规范片段时，可显式降级 BM25。认证失败、collection 缺失、维度不符、编码错误、响应协议无效会显式报错，不假装网络故障。只有旧向量资料时仍不能承诺 BM25 容灾。

模型协议按 index 聚合 tool_calls；相同调用 ID 重复出现不会拼成两个 ID，不一致 ID 拒绝。工具名允许碎片拼接；参数始终追加，不能因为两个 delta 恰好相同而去重。finish_reason 与工具列表不匹配、重复调用编号、越界 index、非法类型或未完整结束都会拒绝。

模型流取消直接打断等待并关闭 HTTP 订阅，不依赖下一段 token 到来。没有把私有 reasoning_content 显示或保存成公开轨迹。

## 7. 验证与部署注意

本轮验证：后端 236 项回归、前端 10 项测试，桌面前端构建与后端打包。使用独立 H2、模拟模型和外部服务，以及回环 HTTP/SSE。前端强制 RESULT→DONE；单独 DONE、半截结果、结束后的额外输出均不能显示成功。真实模型验收脚本也只将观察为 OK 的工具算作成功，没有实际执行该计费脚本。

没有导入私有连接配置，没有调用付费模型，也没有连接真实 MySQL/MinIO/Qdrant 做生产验收。测试证明软件契约，不代表真实模型业务效果。

数据库新增请求编号/指纹、任务规格、产物审核审计和版本字段，并增加请求唯一约束。版本列有初始值 0。启动前备份现有 MySQL；若已有旧的可空 version 列，需先将历史 NULL 初始化为 0，再约束为非空。不要删库或清空历史来“迁移”。旧审核报告没有版本绑定，不能直接用于新合成，可重新复核或明确人工覆盖。

重新启动后端和前端后使用新接口。原音频和论文项目均未被删除或清空。

## 8. 仍待后续升级

- 真实模型与固定策略的同预算成对评测、人工质量标签；现有诊断指标不能替代真实成绩。
- 扩大 RAG 语料，加入困难负例、零召回问题与文档级留出，检验实际 ANN 搜索；原 6 文档诊断报告未被包装成生产召回率。
- 生成模型的精确 token 预算、长会话冲突/遗忘评测；当前 Memory 仍是字符预算和带来源摘记，没有语义冲突自动裁判。
- 持久化 BM25 倒排、增量更新、embedding 模型指纹与迁移；维度检查不能识别同维度不同语义空间。
- 跨数据库/对象存储/向量库的后台对账、分布式会话锁；当前仍有明确的人工作业边界。

适合简历的新增口径：**基于任务规格、产物版本与内容哈希约束 Agent 完成和复核，结合请求幂等、确认审计及中断恢复，增强工具执行可靠性。**不要写成“所有任务必然完成”“端到端 exactly-once”或“已经验证企业级准确率”。
