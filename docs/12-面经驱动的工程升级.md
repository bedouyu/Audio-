# 面经驱动的工程升级

日期：2026-10-10。项目：音频 Agent。

针对[28题审查记录](11-岗位面经对照与简历边界.md)，本轮优先补执行可靠性、完整请求预算、调用关联与缓存失效。没有为了面经名称增加未使用的 Skill/MCP、语义答案缓存或假评测数据。

## 1. 已落地的改动

| 面经中的缺口 | 本轮实现 | 仍须明确的边界 |
|---|---|---|
| MySQL/Redis连续课程状态可能不一致 | MySQL队列/片段作为事实来源；Redis仅带版本快照；课程记录、片段READY、最终知识点完成同事务 | 文件/TTS不属于数据库事务，不承诺端到端exactly-once |
| 单节音频旧入口直接TTS，没有任务防重 | 单节与连续课程复用持久队列，预占request_id/hash，先准备再领取固定audio_id | 不带request_id的兼容请求仍是新任务 |
| 工具一直不返回 | 普通原生工具使用有界worker/队列与等待超时；中断、资源满载、超时明确分类 | cancel是协作中断，不是安全杀线程；委派及审计/独立DAO仍有范围限制 |
| 多实例启动误把其他活实例任务标中断 | run绑定owner，独立节点心跳/租约；仅旧/未知/过期owner残留标中断；过期owner永久fence | 不等于跨实例会话锁、并行Agent或执行级断点恢复 |
| 上下文只数messages字符，漏了tools | 完整请求包含messages、工具schema、选项、协议预留、输出预留与安全余量；HTTP前检查 | 默认保守估算，非生成模型精确token计量 |
| 无工具调用级关联 | event_id、invocation_id、parent_invocation_id、call_id、tool_call_id、parent_call_id、时间及耗时 | 不等于OpenTelemetry、服务端事件重放或完整非侵入Hook平台 |
| 知识更新后缓存失效 | 有界BM25索引缓存，项目/选择片段/内容指纹隔离，变更后重建并显示缓存状态 | 缓存词法索引，不是语义答案缓存；仍从MySQL读当前片段 |
| 联网故障被当作零结果 | 连接/HTTP/协议异常明确失败；基础模式有本机证据可带故障记录继续 | 关闭联网仍是配置行为；不是全依赖自动容灾 |

## 2. 音频队列：数据库是事实来源

新增表：

- `continuous_audio_queues`：用户/项目、request_id/hash、mode、队列状态、领取token、租约、版本。
- `continuous_audio_segments`：队列/序号唯一约束、不可变讲稿及哈希、预分配audio_id、片段状态、版本和审计。

开始任务先锁项目并预占PREPARING，再在事务外生成讲稿。相同用户/项目/request_id且参数相同只读取原任务；改变参数或业务mode拒绝，不重新生成。SINGLE与CONTINUOUS参与请求指纹，不能共用同一编号混淆业务。

课程准备后生成PENDING片段。合成前通过队列锁、领取token和租约控制并发；每段预先分配固定audio_id。只有WAV结构验证通过，才在一个MySQL事务中插入课程记录并将片段变READY；连续课程全部片段READY才完成知识点覆盖。

Redis快照只做最佳努力更新，并用版本比较拒绝旧快照覆盖新快照。查询/继续总是先读MySQL，因此缓存失败不会撤销数据库提交，也不会根据旧缓存重新调用TTS。旧Redis队列保留为只读，既不自动导入，也不删除或回放。

工作执行器固定2个worker，无等待队列。满载立即释放尚未开始的领取并报503；用户可以用原请求编号取回任务，再明确继续。这样不会让租约消耗在长时间排队中。

### 结果未知时怎么办

TTS异常、无有效WAV、租约过期或确认数据库提交失败时，片段进入NEEDS_REVIEW，保留原audio_id。

1. 人工恢复：绑定队列/序号、讲稿哈希、原audio_id，检查原WAV后补记READY，不再次TTS。
2. 人工重置：填写10—500字理由，审计旧尝试并分配新audio_id，回到PENDING；不删除旧文件、不立即TTS，必须再明确继续。

迟到回调需要原token、哈希、audio_id匹配，不能复活已取消队列或覆盖重置后的尝试。

重要残留：准备课程时“预留知识点→关联队列”的崩溃窗口尚未实现完整自动对账。PREPARING结果未知时保守停止，需人工核查；不能宣称规划过程无损续跑。跨机器恢复WAV需要同一主机或共享目录。

核心：[ContinuousAudioStore](D:/desktop/AI/AI音频/audiorag-java/backend/src/main/java/com/bedouyu/audiorag/service/ContinuousAudioStore.java)、[ContinuousAudioService](D:/desktop/AI/AI音频/audiorag-java/backend/src/main/java/com/bedouyu/audiorag/service/ContinuousAudioService.java)。

## 3. API与前端变化

POST `/api/v1/lessons` 现在返回**队列状态**：非终态202，终态200；不再保证同步返回顶层audio_url。播放器等待lessons中已READY的音频。这是旧客户端必须注意的合同变化，本项目桌面端已同步调整。

单节与连续课程均接受可选request_id（UUID）。桌面端网络失败保留原payload和编号，收到队列后才清空；再次主动新建任务使用新编号。

新增：

- POST `/api/v1/continuous-audio/{queueId}/segments/{number}/recover`
- POST `/api/v1/continuous-audio/{queueId}/segments/{number}/reset`

恢复/重置必须提交`confirmed=true`、`expected_script_hash`、`expected_audio_id`；重置另外提交`reason`。GET队列返回mode/status/version/storage及segments审计记录。

界面不会对NEEDS_REVIEW、FAILED或旧Redis队列自动refill；SINGLE也要求独立人工继续。原音频与旧记录均保留。人工理由采用Vue表单，不依赖Electron不支持的prompt输入框。

核心：[AiController](D:/desktop/AI/AI音频/audiorag-java/backend/src/main/java/com/bedouyu/audiorag/controller/AiController.java)、[AudioPanel](D:/desktop/AI/AI音频/audiorag-java/desktop/src/renderer/src/components/AudioPanel.vue)、[前端恢复策略](D:/desktop/AI/AI音频/audiorag-java/desktop/src/shared/audio-queue-policy.js)。

## 4. 工具等待、取消与有状态操作

普通原生工具的归属查询和实际执行都进入有界线程池。默认4worker、16排队容量、30秒等待，并受根运行剩余时限限制。线程池满载明确TOOL_BUSY；关闭、取消和TOOL_TIMEOUT各有结果。

delegate_agent同步执行，子工具再进池，避免所有worker等待嵌套worker的死锁。其内部独立DAO与事件落库不由通用Future硬终止，不能说“所有代码都有硬超时”。

工具作用域只在线程内生效，成功结束或超时后失效。过期worker不能继续发成功事件；保存候选、读取检查账本和完成会话前增加活跃/租约检查。

`FunctionTool.hasSideEffects()`声明有状态操作。任务规格声明和委派属于有状态工具。实际写入开始后发生等待超时，整轮停止并标注outcome_uncertain；不能把写入未知结果当成普通失败后自动继续尝试。取消Future不能撤销已发生的外部副作用。

根预算采用单调时钟；原生模型HTTP与流正文共用min(120秒,根剩余时限)。底层超时时根deadline已到，运行保留LIMIT_REACHED，而不是误标普通FAILED。会话忙冲突已改为业务409。

核心：[工具执行器](D:/desktop/AI/AI音频/audiorag-java/backend/src/main/java/com/bedouyu/audiorag/tools/FunctionToolExecutor.java)、[有界执行资源](D:/desktop/AI/AI音频/audiorag-java/backend/src/main/java/com/bedouyu/audiorag/tools/execution/ToolExecutionRuntime.java)、[共享预算](D:/desktop/AI/AI音频/audiorag-java/backend/src/main/java/com/bedouyu/audiorag/core/loop/AgentBudget.java)。

## 5. 实例心跳与安全残留处理

新增`agent_runtime_nodes`和`agent_runs.owner_id`。每个进程随机owner，默认10秒心跳、90秒租约，心跳使用独立短事务、不依赖run行锁。

节点过期永久EXPIRED，不允许迟到心跳复活同一owner。启动和读取只处理旧/未知/过期owner的RUNNING，活owner不受其他实例启动影响。晚到成功也不能将已中断任务改回成功。SIGKILL后可能保守等待租约到期，不能立即假定旧进程已死亡。

这只解决运行owner存活与残留识别，不是完整多实例编排：仍无跨实例同会话锁或运行栈恢复。独立草稿确认TTS的旧启动恢复逻辑仍按单实例使用，不能把队列租约推广到所有写入。

核心：[AgentRuntimeLeaseService](D:/desktop/AI/AI音频/audiorag-java/backend/src/main/java/com/bedouyu/audiorag/service/runtime/AgentRuntimeLeaseService.java)、[租约事务](D:/desktop/AI/AI音频/audiorag-java/backend/src/main/java/com/bedouyu/audiorag/service/runtime/AgentRuntimeLeaseStore.java)、[AgentRunStore](D:/desktop/AI/AI音频/audiorag-java/backend/src/main/java/com/bedouyu/audiorag/service/AgentRunStore.java)。

## 6. 完整生成请求预算

NativeFunctionCallingGateway与基础LlmGenerationService（聊天/单节/课程）都使用同一ModelContextBudget。发送前计入完整JSON请求、messages、工具schema、选项、协议开销、输出预留和安全余量；超预算在HTTP前拒绝，不冒充本地fallback成功。

原生循环可以先压缩模型已看过的旧工具观察再检查一次；最新观察、assistant/tool配对和必要reasoning_content不静默删改，仍超限则停止。发送前拒绝不消耗一次实际模型尝试预算。

TokenCounter提供模型特定适配入口。当前默认UTF-8字节保守估算，整个请求标记estimated；没有安装DeepSeek生成tokenizer，也不把BGE tokenizer当生成计数器。默认65536是**本机保守cap**，不是自动查得的供应商窗口，换模型需明确核验/配置。

分项计数是诊断，不保证相加等于整体JSON计数；协议模板可能不同，因此即使未来有精确字符串tokenizer，也不能直接声称供应商请求计量精确。DeepSeek官方同样提醒离线tokenizer计量可能与处理后的usage不同。[官方Token说明](https://api-docs.deepseek.com/quick_start/token_usage/)。

完整成功后才记录供应商usage，失败/截断流不当作成功用量。前端分别展示预算估算与供应商报告，不用估算冒充实际token或费用。

核心：[ModelContextBudget](D:/desktop/AI/AI音频/audiorag-java/backend/src/main/java/com/bedouyu/audiorag/ai/ModelContextBudget.java)、[TokenCounter](D:/desktop/AI/AI音频/audiorag-java/backend/src/main/java/com/bedouyu/audiorag/ai/token/TokenCounter.java)、[原生网关](D:/desktop/AI/AI音频/audiorag-java/backend/src/main/java/com/bedouyu/audiorag/ai/NativeFunctionCallingGateway.java)。

## 8. 索引缓存与显式网络故障

BM25缓存以项目＋规范片段内容指纹为key，指纹包含文档、顺序、区间、token元数据和实际文本哈希。当前请求仍读取事实库，新增/删除/改文/改变文档子集必定得到新指纹。容量默认16项目索引、总200万文本字符；大条目绕过缓存，LRU淘汰。容量是字符权重而非精确堆内存计量。

前端能看到HIT/MISS_REBUILT/BYPASS_CAPACITY和index_revision。缓存的是BM25索引，不是语义回答，不能回答成个人/公共问题池或语义答案缓存失效。

联网搜索的有效空RSS仍是零结果；连接超时、HTTP异常、非RSS/DTD等协议错误明确失败。基础检索有本机证据时可以带网络失败记录继续，无任何证据时不把网络失败伪装成没有相关资料。

核心：[Bm25IndexCache](D:/desktop/AI/AI音频/audiorag-java/backend/src/main/java/com/bedouyu/audiorag/rag/index/Bm25IndexCache.java)、[WebSearchService](D:/desktop/AI/AI音频/audiorag-java/backend/src/main/java/com/bedouyu/audiorag/tools/research/WebSearchService.java)。

## 9. 配置、迁移与验证

2. 配置默认`ddl-auto=update`时，启动新增队列/片段/节点表与owner列；若关闭自动DDL，需由管理员按新实体增补字段/约束，不要删库。

4. 旧Redis和音频文件不会自动清理，旧队列只读；需要新的执行任务时明确新建，不能自动导入回放。
