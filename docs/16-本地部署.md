# 本地部署

从一台干净的 Windows 机器开始，把后端、桌面端和依赖服务跑起来。只想在已有环境里启动，直接看「最短路径」。

## 这套系统由什么组成

| 组件 | 技术 | 默认地址 | 必需 |
| --- | --- | --- | --- |
| 桌面端 | Electron + Vue 3 | 开发模式 `http://127.0.0.1:5174` | 是 |
| 后端 | Spring Boot 4 / Java 17 | `http://127.0.0.1:18081` | 是 |
| MySQL | MySQL 8.4 | `127.0.0.1:3306/docpilot` | 是 |
| Redis | Redis 7 | `127.0.0.1:6379` | 是 |
| Qdrant | qdrant | `127.0.0.1:6333` | 是 |
| MinIO | MinIO | `127.0.0.1:9000`（控制台 9001） | 是 |
| 模型 API | DeepSeek 兼容接口 | `https://api.deepseek.com` | 是 |
| 向量模型 | BGE small zh | 本地目录 | 是 |
| 本地语音 | CosyVoice 3（可选） | `127.0.0.1:50000` | 否，可用 Windows SAPI |

## 1. 前置条件

| 依赖 | 版本 | 说明 |
| --- | --- | --- |
| Windows | 10 / 11 | 启动脚本是 PowerShell，路径按 Windows 写 |
| Docker Desktop | 任意较新版本 | 提供 MySQL / Redis / Qdrant / MinIO |
| JDK | **17**（必须） | 脚本会校验主版本，不是 17 直接报错 |
| Maven | 3.9+ | 构建后端 jar |
| Node.js | 20+ | electron-vite 4 / Vite 7 的要求 |
| Python | 3.10（可选） | 只有部署 CosyVoice 本地语音时需要，见 [CosyVoice 本地语音部署](14-CosyVoice本地语音部署.md) |

脚本查找工具链的顺序是 **环境变量 → 已知路径 → PATH**，所以换机器时用环境变量最省事：

```powershell
setx JAVA_HOME  "C:\Program Files\Java\jdk-17"
setx MAVEN_HOME "C:\apache-maven-3.9.9"
setx NODE_HOME  "C:\Program Files\nodejs"
```

设置完要**新开一个终端**才生效。

## 2. 最短路径

```powershell
git clone <仓库地址>
cd audiorag-java

# 1) 生成私有配置（该文件已被 .gitignore 排除，不会提交）
copy backend\config\application-private.example.yml backend\config\application-private.yml

# 2) 编辑它，填入与 docker 一致的口令（见 3.3）
#    MySQL 用户/口令、MinIO access/secret

# 3) 设置模型密钥（用户级环境变量，设置后重开终端）
setx DEEPSEEK_API_KEY "你的密钥"

# 4) 一键启动
start-all.cmd
```

`start-all.cmd` 会依次：启动 Docker Desktop（未运行时）→ 起依赖容器 → 等端口就绪 → 构建并启动后端 → 等健康检查通过 → 启动桌面端。

可选参数：

```powershell
start-all.cmd -SkipDocker            # 依赖服务已经在跑
start-all.cmd -SkipFrontend          # 只起后端
start-all.cmd -ComposeFile D:\path\docker-compose.yml
```

## 3. 分步部署

### 3.1 依赖服务

仓库自带 compose 文件 `docker/ai-services.yml`（MySQL / Redis / Qdrant / MinIO）：

```powershell
docker compose -f docker/ai-services.yml up -d
docker compose -f docker/ai-services.yml ps
```

| 服务 | 端口 | 数据卷 | 默认口令 |
| --- | --- | --- | --- |
| mysql | 3306 | `mysql-data` | 库 `docpilot`，用户 `docpilot` / `docpilot_mysql_dev`，root `docpilot_root_dev` |
| redis | 6379 | `redis-data` | 无 |
| qdrant | 6333 / 6334 | `qdrant-data` | 无 |
| minio | 9000 / 9001 | `minio-data` | `docpilot` / `docpilot_minio_dev` |

这些口令是**公开的开发默认值**，只能用于本机。要改就覆盖环境变量，或用自己的一份 compose：

```powershell
$env:MYSQL_PASSWORD = '改掉的口令'
$env:MINIO_ROOT_PASSWORD = '改掉的口令'
docker compose -f docker/ai-services.yml up -d
```

如果本机已经有自己的服务栈（例如 `D:\AI-Services\docker-compose.yml`），`start-all` 会优先用它；也可以用 `-ComposeFile` 或环境变量 `AUDIORAG_COMPOSE_FILE` 明确指定。

### 3.2 数据库

只需要**库存在**——compose 里已经用 `MYSQL_DATABASE=docpilot` 建好。表由 Hibernate 的 `ddl-auto=update` 在首次启动时自动创建，不需要手工执行 SQL。

验证：

```powershell
docker exec docpilot-mysql mysql -udocpilot -pdocpilot_mysql_dev -e "use docpilot; show tables;"
```

### 3.3 后端配置

后端会加载 `backend/config/application-private.yml`（相对**工作目录**，所以要在 `backend/` 下启动）。这个文件含口令，已在 `.gitignore` 中，只提交了 `application-private.example.yml`。

必填项：

```yaml
spring:
  datasource:
    username: docpilot
    password: docpilot_mysql_dev
audiorag:
  minio:
    access-key: docpilot
    secret-key: docpilot_minio_dev
```

常用可选项（默认值不合适时再写）：

| 配置项 | 环境变量 | 默认值 |
| --- | --- | --- |
| 向量模型目录 | `AUDIORAG_EMBEDDING_MODEL_DIR` | `D:/AI-Toolchain/models/bge-small-zh-v1.5`（**换机器必须改**） |
| 语音提供方 | `AUDIORAG_SPEECH_PROVIDER` | `windows` |
| CosyVoice 地址 | `AUDIORAG_COSYVOICE_URL` | `http://127.0.0.1:50000` |
| 模型名 | `AUDIORAG_LLM_MODEL` | `deepseek-flash` |
| 模型密钥 | `DEEPSEEK_API_KEY` / `AUDIORAG_LLM_API_KEY` | 空 |
| 复核专用模型 | `AUDIORAG_LLM_REVIEW_MODEL` | 空（与主流程共用） |
| 数据库地址 | `AUDIORAG_MYSQL_URL` | `jdbc:mysql://127.0.0.1:3306/docpilot` |
| 音频输出目录 | `AUDIORAG_AUDIO_DIR` | `../data/generated-audio` |

### 3.4 向量模型

检索需要本地 BGE 模型目录，默认值指向作者机器的 `D:/AI-Toolchain/models/bge-small-zh-v1.5`。**换机器必须改成自己的路径**：

```powershell
setx AUDIORAG_EMBEDDING_MODEL_DIR "D:\models\bge-small-zh-v1.5"
```

目录里应有模型权重与 tokenizer 文件（从 HuggingFace / ModelScope 下载 `BAAI/bge-small-zh-v1.5`，约 100MB）。

### 3.5 模型密钥

```powershell
setx DEEPSEEK_API_KEY "sk-..."
```

只影响新开的进程。启动器会自动沿用 Windows 系统代理（`-Djava.net.useSystemProxies=true`），同时对本机环回地址强制直连，保证 MySQL / MinIO / Qdrant 不走代理。

### 3.6 语音

- **Windows SAPI（默认）**：零依赖，能出声但机械。中文音色取决于系统已安装的语音。
- **CosyVoice 3（可选）**：自然得多，也能**从样例录音克隆音色**。部署步骤、模型下载、venv 与音色录入见 [CosyVoice 本地语音部署](14-CosyVoice本地语音部署.md)。

切换方式：设置 `AUDIORAG_SPEECH_PROVIDER=cosyvoice`，或写入 `runtime/speech-provider.txt`（启动器会读取）。CosyVoice 未就绪时后端会在合成阶段回 503，并说明原因。

### 3.7 启动后端

```powershell
.\start-backend-local.cmd          # 构建 + 启动，健康检查 18081
```

手工方式：

```powershell
cd backend
mvn -DskipTests package
java -Dfile.encoding=UTF-8 -Djava.net.useSystemProxies=true -jar target/audiorag-backend.jar
```

- 端口 `18081`，默认只绑定 `127.0.0.1`（改 `SERVER_PORT` / `SERVER_ADDRESS`）。
- 必须在 `backend/` 目录下运行，否则读不到 `config/application-private.yml`。
- 打包前先停掉正在运行的后端，否则 Windows 会锁住 jar 导致改名失败。

### 3.8 启动桌面端

```powershell
cd desktop
npm install
npm run dev
```

Electron 窗口出现；也可以直接用浏览器打开 `http://127.0.0.1:5174`（`dsh web` 之外的独立用法，仅开发模式可用）。

## 4. 构建产物与打包

| 目标 | 命令 | 产物 |
| --- | --- | --- |
| 后端 jar | `mvn -DskipTests package` | `backend/target/audiorag-backend.jar`，可 `java -jar` 直接部署 |
| 桌面端资源 | `npm run build`（在 `desktop/`） | `desktop/out/`（主进程 / preload / 渲染层） |
| 全量构建 + 测试 | `build-all.cmd` | 同上，并跑后端与桌面端测试 |

**当前没有安装包（.exe / .msi）配置**：仓库未引入 electron-builder，`npm run build` 只产出可运行资源，`npm start` 是预览构建产物。要分发安装包需要自行加 electron-builder 及签名配置。

## 5. 验收清单

| 检查 | 命令 | 期望 |
| --- | --- | --- |
| 依赖服务监听 | `docker compose -f docker/ai-services.yml ps` | 四个服务 running |
| 四个端口 | 3306 / 6379 / 6333 / 9000 | 监听中 |
| 后端健康 | `curl http://127.0.0.1:18081/api/health` | `status: ok` |
| 语音就绪（可选） | `curl http://127.0.0.1:50000/health` | `ready: true` |
| 音色列表 | 登录后 `GET /api/v1/audio/voices` | 至少一个 `enabled: true` |
| 端到端 | 桌面端登录 → 新建内容空间 → 说一句想听什么 | 生成音频并可播放 |

## 6. 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| `JDK 17 was not found` | `JAVA_HOME` 指向的不是 17；脚本只接受主版本 17 |
| `Maven / Node.js was not found` | 设置 `MAVEN_HOME` / `NODE_HOME`，或装到 PATH |
| Docker 引擎未运行 | 启动器会尝试拉起 Docker Desktop 并等待约 4 分钟；失败就手动打开后再跑 |
| 端口 3306 被占用 | 本机已有 MySQL；改 compose 端口并同步 `AUDIORAG_MYSQL_URL`，或停掉旧实例 |
| 后端报数据库连接失败 | `application-private.yml` 口令不对、文件没放在 `backend/config/`，或不是从 `backend/` 启动 |
| 脚本中文乱码 / 解析失败 | `.ps1` 必须是 **UTF-8 with BOM**；编辑工具保存时别去掉 BOM |
| 模型调用 401 / 超时 | `DEEPSEEK_API_KEY` 未生效（改完要重开终端）或代理不通 |
| 语音合成 503 | CosyVoice 还没 ready（看 `runtime/cosyvoice-*.err.log`），或音色未注册 |
| 检索报错 / 维度不匹配 | `AUDIORAG_EMBEDDING_MODEL_DIR` 指错或换了别的向量模型 |
| 桌面端窗口不出现 | 外部工具把 `ELECTRON_RUN_AS_NODE=1` 留在环境里；启动器已清理，手工运行前先 `Remove-Item Env:ELECTRON_RUN_AS_NODE` |
| 生成的中文音频时长偏长 | 语速常量按实测校准（中文约 193 字/分钟）；英文篇幅仍可能略长，属已知问题 |

## 7. 停止与清理

```powershell
docker compose -f docker/ai-services.yml stop      # 停止，保留数据
docker compose -f docker/ai-services.yml down       # 停止并删除容器
docker compose -f docker/ai-services.yml down -v    # 连同数据卷一起删除（不可恢复）
```

后端用 `Ctrl+C` 停止（已配置优雅关闭）。可以安全删除的运行时产物：`data/generated-audio/`（生成的音频）、`runtime/*.log`、`desktop/out/`、`backend/target/`。
