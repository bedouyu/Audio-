# 讲稿差异审阅与确认

日期：2026-10-24。按用户最新要求，已有讲稿的改动必须先展示红绿差异，由用户确认或放弃。本记录更新 17、18 文档中的失焦自动应用及不增加操作按钮约束。

## 使用方式

- 手工编辑当前生效讲稿，下面同步展示差异；绿色表示新增，红色删除线表示删除。点击“提交审阅”后保存为待审修改，尚未覆盖正文。
- 左侧说出改一段、整篇改格式、续写或撤回要求，助手直接准备修改单。自然语言制作入口中的“缩短刚才的讲稿”等修改也进入同一审核流程，不另建队列直接合成。
- 在待确认修改中点击“确认修改”，才替换受影响的正文并开始按需合成；“保留原稿”放弃本次修改，原正文及音频保留。
- 需要跨语言修改时直接说明目标语言与体裁；默认沿用当前音色，确认处也可改选兼容音色。详见 [跨语言与体裁改稿修复](20-跨语言与体裁改稿修复.md)。
- 最近修改记录中点击“撤回此修改”，会创建一份反向修改，仍先审阅再确认。整篇改稿和续写都保留原分段用于恢复。
- 翻页、失焦和离开页面不再自动应用修改。未提交输入保留在当前账号的程序内存中；服务端待审版本持久保存，重启后可继续审核。关闭程序后的本地未提交输入恢复不在本次范围。

首版没有旧稿可比较，展示完整正文；同任务 Agent 草稿修订显示与上一稿的差异。独立新主题依然创建新内容。

## 审核修复

原手动确认入口只认指定报告的 `approved=true` 与稿件绑定，没有检查它是否是最新报告，以及七项检查、问题列表是否一致。前端也可能显示不完整报告为通过。

现在自动消费、手动合成与前端预检统一采用同任务、同稿件编号、同正文哈希的最新复核。主题、体裁、语言、结尾、篇幅、引用、朗读适配七项必须完整，通过报告不得含未解决问题。旧通过报告不能覆盖新拒绝结果。页面展示逐项检查、问题及理由；人工覆盖仍须明确填写原因并留下审计。音色选择使用真实服务列表，默认按语言自动选择。

回归另发现连续报告可能因数据库时间精度并列，退化为按随机编号判断新旧。现在在任务锁内为新产物分配严格递增的毫秒时间；旧报告若同一稿件、同内容的创建时间完全并列，则不直接当作通过凭据。已加入连续三次验证及数据库回读时间断言。

## 接口与一致性

新增表 `continuous_audio_script_revisions` 保存原稿、提案正文、原分段、版本基线、状态与用户操作时间；`audio_instruction_receipts.request_action` 记录自然语言修改类型。沿用项目当前 `ddl-auto=update` 方式初始化。

现有 `revise`、`rewrite`、`extend`、`undo` 接口现在返回原队列快照、`script_revisions` 列表及本次 `script_revision`，语义改为提出修改。外部调用方需要显式调用确认接口：

| 方法与路径（队列前缀 `/api/v1/continuous-audio/{queueId}`） | 用途 |
| --- | --- |
| `GET /script-revisions` | 查询待审与最近处理记录 |
| `POST /script-revisions/{revisionId}/accept` | 确认并应用不可变修改单 |
| `POST /script-revisions/{revisionId}/reject` | 放弃修改、保留原稿 |
| `POST /script-revisions/{revisionId}/revert` | 为已确认修改创建反向提案 |

三个操作接口均要求请求体 `{"confirmed":true}`，验证用户及队列归属。状态包括 `PENDING`、`ACCEPTED`、`REJECTED`、`STALE`、`UNCHANGED`。最多同时保留 20 份待审修改，快照始终包含全部待审项和最近处理项，合计最多 30 条。

确认在队列锁内比较正文、段号、版本及音频尝试编号；原稿变化或目标分段被删除时将提案标记过期，返回 409，不覆盖最新正文。重复确认只读回结果，不重复合成；确认事务提交后才派发语音任务。自然语言请求编号持久去重，拒绝或无变化后重放均不再次改写。回退若已遇到后续正文改动会拒绝覆盖，需根据当前稿另行提出修改。

差异算法按中文字符、英文词及空白分词，展示始终使用纯文本节点；复杂长稿采用有界预算并保留完整修改区，不执行稿件中的 HTML。

## 验证

验证记录在 `.cache/script-review-20261024-verify.log`、`.cache/script-review-20261024-desktop-tests.log` 和 `.cache/script-review-20261024-desktop-build.log`。后端使用独立构建目录 `.cache/verification-20261024/backend/`，不覆盖运行中的 JAR。

最终结果：后端 `clean verify` **614 项通过，0 失败、0 错误、0 跳过**；桌面端 **80 项通过**，生产构建成功。后端新增集成测试 `ScriptRevisionHttpIntegrationTest` 经过真实 HTTP、业务服务和 H2 数据库事务，验证确认前正文及音频不变、重复确认不再合成、拒绝后重放、其他账号无法确认、过期状态实际提交及精确回退。

回归覆盖提案持久化、确认前不调用语音、不改原文、拒绝、重复确认、越权、过期、精确回退、自然语言入口、最新复核绑定、红绿差异还原、页面交互、轮询与切队列迟到回包。外部模型和语音使用测试替身，本轮未进行真实 DeepSeek 内容评测或 CosyVoice 听感验收。
