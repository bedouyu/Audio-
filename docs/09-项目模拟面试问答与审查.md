# AudioRAG 项目模拟面试：问答记录与可辩护边界

记录日期：2026-10-09。对象：简历中的 Agent、Memory、RAG 三条项目描述。

更新说明：本文保留升级前的审查快照。后续已修复的完成判定、版本复核、请求幂等、并发确认及取消等问题，见[Agent可靠性升级记录](10-Agent可靠性升级记录.md)；不要把本文旧代码描述当作当前实现。

本记录由 AI 分别模拟面试官、候选人和技术审查者，共 30 组主问题，附追问与据实回答。不是用户的真实作答，也不代表已通过真实面试。回答用于学习和演练，不能照背后把未掌握的内容说成自己已经掌握。

核查方式：读取当前源码、已有测试报告和本地实验报告；没有修改业务代码，没有读取私有配置或密钥，没有启动生产服务、调用付费模型或重新运行测试。已有后端报告记载 117 项测试、0 失败、0 错误，不能据此宣称生产环境或真实模型业务效果已验收。

## 一、结论先行

**有条件通过项目层面的技术自洽审查，但不能包装成已完成企业级生产验证。**

- 可据实讲：自研原生工具循环、同步多 Agent 委派、应用层权限、可追溯产物、同会话记忆策略、轻量独立 BM25、RRF、RSE 排名近似组合、人工确认与已提交状态下的幂等控制。
- 必须限定：摘记不是 LLM 摘要；预算主要按字符计量；RSE 不是完整 dsRAG；支持模型选策略不等于已经证明选得好；状态恢复不是无损恢复推理；人工确认不是强制复核通过或 exactly once。
- 深挖会卡住：真实模型成对评测不足、完成判定的关键词启发式、复核与具体产物绑定不足、跨存储失败窗口、并发状态收敛、持久化检索索引与 embedding 迁移。

面试通过与否还取决于候选人能否现场讲清公式、调用链、失败路径，并独立修改或复现代码。以下“候选人回答”只说明项目存在可辩护口径，不证明用户已经具备这些能力。

## 二、30 组模拟问答

### Q01｜先用一分钟介绍项目，不要只背技术栈

**面试官：** 项目解决什么问题，Agent 到底做了什么？

**候选人：** 这是本机音频学习系统。用户导入笔记、字幕或音频转写，再提出学习目标。主控可直接检索回答，也可委派学习规划、资料研究、讲稿编写和内容复核。模型负责选择下一步工具，后端负责实际执行、权限、预算和状态。计划和讲稿先形成可追溯草稿，用户确认后才应用计划或合成本机音频。核心工作是 Agent 运行时、上下文管理和证据检索，不是只做一个聊天界面。

**追问：** 那普通问答是不是也要跑四个 Agent？

**候选人：** 不需要。主控可直接处理；专业 Agent 按需委派，避免强制走固定完整流水线。是否更省成本尚无真实业务统计，不能先报效果数字。

**审查：** 自洽。必须能画出“入口—主控—工具/子 Agent—产物—确认执行”调用链。证据 A1、A2、A7。

### Q02｜为什么算 Agent，ReAct 和 Function Calling 有何区别？

**面试官：** 有工具调用就等于 ReAct 吗？

**候选人：** Function Calling 是结构化表达工具意图的协议；ReAct 式运行时是决策、行动、观察交替的控制循环。我的循环调用模型，收到 tool_calls 后执行工具，将真实结果按调用编号回灌，再让模型决策。没有调用时还要通过输出检查，不是直接把模型一句“完成”当成功。系统没有要求公开完整思维链；供应商需要回传的 reasoning_content 只在当前协议内保留，不写公开轨迹。

**追问：** 你复现了 ReAct 论文全部做法和实验吗？

**候选人：** 没有。准确说法是自研 ReAct 式执行框架，借鉴推理与行动交替思想，不声称复现论文全部提示格式、算法效果或公开推理轨迹。

**审查：** 可辩护，但需把“协议”“控制循环”“私有推理”分开。证据 A1、A3；方法背景见 [ReAct 原论文](https://arxiv.org/abs/2210.03629)。

### Q03｜多 Agent 是否只是一个提示词里扮演多个角色？

**面试官：** 同一个模型凭什么叫多 Agent？能并行吗？

**候选人：** 每个专业 Agent 有自己的 profile、提示词、工具白名单、独立模型消息和循环限制。主控通过 delegate_agent 选择角色与输入产物，子 Agent 输出保存为产物。是否使用同一个基础模型，不改变这些职责和运行上下文的分离。当前委派是同步串行，父循环等待子循环结束；同轮多个工具也顺序执行，没有并行 DAG 调度。

**追问：** 入口线程池有两个线程，不就是并行吗？

**候选人：** 那是处理不同请求，不是单任务内的子 Agent 并行。不能混淆并发请求和并行编排。

**审查：** “多 Agent 协作”成立；“并行多 Agent”不成立。证据 A2、A8。

### Q04｜独立上下文与工具权限靠提示词还是代码？

**面试官：** 子 Agent 猜到另一个产物 ID，能读到吗？

**候选人：** 子 Agent 用空主控历史启动，child 不自动继承主控 memory 和最近任务记录。工具定义按 profile 过滤，执行时再次核验白名单及项目归属；产物读取还检查显式传入的 artifact IDs 和数据库归属。它们共享用户、项目、预算、事件出口及证据账本，所以是应用层的上下文和权限隔离，不是进程沙箱或完全信息隔离。

**追问：** 共享证据会不会污染子 Agent 产物？

**候选人：** 有这个边界。目前保存子产物时附带整个根任务账本，而非仅当前产物真正引用的来源；“有出处”不能等同于每条证据都被该产物使用。后续需要产物级证据子集。

**审查：** 基础隔离可讲；不能说零信任沙箱或证据完全隔离。证据 A2、A4、A9。

### Q05｜流式工具参数怎么聚合，结果如何回灌？

**面试官：** arguments 分成多段，甚至多个调用交错返回，怎么办？

**候选人：** 网关按 tool_call index 聚合 id、名称和 arguments，用有序映射维护调用顺序。只有模型轮次出现可接受的结束原因，才把调用交给执行器；每个观察以原 tool_call_id 返回，与 assistant 的 tool_calls 组成完整轮次。参数 JSON 和工具允许清单在执行前校验。

**追问：** 收不到 DONE 呢？stop 却带工具调用呢？

**候选人：** 当前不强制收到 DONE，合法 finish_reason 后 EOF 也会接受；也没有明确拒绝 stop 加非空调用的组合。已有测试不是完整供应商协议矩阵，交错、多调用、重复碎片和不一致结束原因仍需增加测试。

**审查：** 基本实现成立，不能宣称覆盖所有流式边界。证据 A3、A4、T1。

### Q06｜循环何时停止，子 Agent 会不会绕过预算？

**面试官：** 如何防止模型一直查资料或者反复委派？

**候选人：** 根任务和子 Agent 共用一个预算对象：默认最多 24 次模型调用、32 次工具尝试、8 次委派、10 分钟；各角色还有最大轮数。相同 Agent、工具及参数第三次出现时终止。失败或越权尝试也会消耗预算，不能通过不断试错绕过限制。输出校验失败只允许一次修正。

**追问：** 这是不是 token 或费用预算？重复检测是不是幂等？

**候选人：** 不是。这里是次数和时间控制；参数只做顶层键排序，未递归规范化。重复检测用于防循环，不是结果缓存或 exactly once。时间检查是协作式，不能抢占所有阻塞调用。

**审查：** 有界执行可讲；精确费用控制、硬时限、递归参数规范化没有实现。证据 A1、A4、A5。

### Q07｜怎么证明任务真的完成，而不是模型嘴上说完成？

**面试官：** 你检查了产物，是否就保证用户目标达成？

**候选人：** 检查包括非空输出、引用编号、角色要求的工具调用、计划/复核结构、讲稿长度，以及部分生成请求是否产生真实产物。但这是基础契约，不是语义完成证明。当前主控还用中文关键词判断是否必须生成，工具成功集合也只记录名称，没有完整任务覆盖清单。

**追问：** “生成课程讲稿，不要用公式”是否会漏检？空检索是否算成功？

**候选人：** 源码中包含“不要”等词会让部分生成检查跳过，因此这类组合请求存在漏检风险；NO_RESULTS 和 TRUNCATED 也会被当成非 ERROR 工具记录。这需要独立任务规格、状态化覆盖条件和更细的工具结果判定来补强，不能用现有验证器声称完成率保证。

**审查：** 高风险追问。上述漏检是源码可推导行为；本轮未做真实模型复现。证据 A1、A6。

### Q08｜人工确认是否意味着复核通过才能执行？

**面试官：** confirmed=true 能证明人真的读过吗？

**候选人：** 真实计划应用和音频合成不开放给 Agent 工具，由认证用户调用独立接口，并要求 confirmed=true。计划再次校验结构；音频执行检查类型和状态。这个字段是显式请求门槛，不证明用户阅读了内容，也没有独立批准凭证或内容哈希签名。复核不通过目前是建议与提示，不是服务端强制禁止执行的门槛。

**追问：** 复核检查是否绑定同一份讲稿？

**候选人：** 当前检查通过标志是上下文 Boolean，读取和校验主要按工具名称记录，没有把被检查 artifact ID、版本和复核结论强绑定。不能说已经保证“复核过的就是最终执行的那份”。

**审查：** 人工确认流程成立；强审批和复核绑定不足。证据 A6、A7、A10。

### Q09｜你说幂等，能保证 exactly once 吗？

**面试官：** TTS 文件生成后、数据库提交 READY 前崩溃，会怎样？

**候选人：** 合成先在短事务里锁产物并置 GENERATING，提交后执行 TTS，再用另一个事务写 READY。READY 的重复确认复用结果，GENERATING 拒绝并发重复执行。计划应用与 APPLIED 在同一数据库事务中完成，另有项目锁和知识点 hash 去重。文件系统和数据库没有统一事务，所以只能讲已提交状态下的重复确认控制，不是端到端 exactly once。

**追问：** 重启是否可能重复合成或遗留孤儿文件？

**候选人：** 是。崩溃窗口可能留下文件，重启标 NEEDS_REVIEW 后人工重试会产生新 audio ID。当前没有完整对账与跨系统事务；聊天请求也没有持久化幂等键。

**审查：** 正确解释限制就可辩护；不能保证所有失败下仅执行一次。证据 A7、P1、P2。

### Q10｜重启后到底恢复了什么？并发、取消如何处理？

**面试官：** 轨迹落库是否等于从第 N 次工具调用继续？

**候选人：** 任务、事件和产物落库，重启将 RUNNING 标 INTERRUPTED、GENERATING 标 NEEDS_REVIEW，不自动重放。继续会创建新 run，读取最近目标、状态及产物。transcript、call IDs、成功工具集合和剩余预算没有持久化，因此不是无损断点续跑。会话回合锁只在单进程内；取消依赖中断检查、请求超时及关闭响应流，不保证所有阻塞工具立即退出。

**追问：** 数据库锁能让 run 和所有产物状态原子收敛吗？

**候选人：** 不能。主要锁单个产物和项目，run 没有对应锁或版本保护。用户在主控 finish 前确认产物时，旧产物快照可能让 run 最后仍写待确认。这个竞态是静态推导风险，本轮未做并发故障注入。

**审查：** “状态参考与保留产物”成立；无损恢复、集群锁、原子收敛不成立。证据 A2、A8、P1、P3、M5。

### Q11｜Memory 与 RAG 有什么区别，为什么不共用所有数据？

**面试官：** 两边都有 BM25，区别是什么？

**候选人：** Memory 主要恢复当前会话目标、约束、讨论和任务状态；RAG 检索用户导入的项目资料作为回答证据。两边可以复用词法算法，但数据范围、时效和可信等级不同。用户旧偏好不是外部事实证据，旧 assistant 回答也不能直接当真。当前记忆工具会话级，资料工具项目级，不默认开启跨会话画像。

**追问：** 新开会话能继承旧偏好吗？

**候选人：** 当前不自动继承。要做用户级或项目级长期记忆，需要另外定义授权、覆盖、过期与删除规则，不能直接把全部旧聊天混进来。

**审查：** 数据职责清楚；别说已实现长期用户画像。证据 M1、M4、R1。

### Q12｜保存完整历史，是不是每次都全量发送？

**面试官：** 几千轮以后怎么办？

**候选人：** 完整原始消息保存在 MySQL，本次上下文另外打包，最多扫描最近 400 条消息。窗口之外，仅已保存且校验通过的原文摘记可能进入上下文，最多 32 条；知道 source ID 时可以分段重读。没有全库历史搜索和首次升级全文回填，旧事实可能找不回，不能承诺无限记忆。

**追问：** 旧目标没有关键词又早于 400 条呢？

**候选人：** 可能丢失，这是当前方案明确的限制；完整持久化并不等于完整可召回。

**审查：** 诚实边界可讲，不能包装为无限长上下文。证据 M1、M2、M4。

### Q13｜四种 Memory 方法具体差在哪里？

**面试官：** hybrid 是否用了向量？“继续”如何检索？

**候选人：** recent_window 取近轮；query_recall 加 BM25 历史召回；extractive_notes 加用户原文摘记；hybrid 组合三者。Memory 的 hybrid 没有向量。历史召回把旧消息按最多 600 字符分段，用中文单字/二元词和英文连续词统计 BM25；纯继续型请求会参考最近非继续型用户问题，而不是从 assistant 猜目标。

**追问：** “预算”和“花多少钱”能稳定匹配吗？

**候选人：** 不能保证。它是词法方法，不是语义检索；复杂同义、指代和隐含偏好是薄弱项。初始策略由配置或前端确定，主控需要时可通过 memory_search 再选策略，不是已训练的自动最优路由。

**审查：** 多策略成立；语义记忆和最优自动选择未实现。证据 M2、M4、R3。

### Q14｜原文摘记是不是摘要？旧约束如何被新约束覆盖？

**面试官：** 从“500元”改成“200元”，系统会删掉旧数字吗？

**候选人：** 摘记按目标、需求、约束和更正等关键词抽用户原句，每条最多 300 字符，保留原文范围与时序；它不是模型摘要或结构化事实状态。候选会优先更正词和近期内容，但不会自动判定事实真假、删除旧约束或完成语义覆盖。当前请求和较晚更正优先是模型提示规则，需要时可重读原文。

**追问：** 能保证 latest-wins 吗？

**候选人：** 不能。旧要求仍可能同时存在，摘记也可能被 32 条上限淘汰；提示不是遵守保证，需要回答级冲突测试。

**审查：** 原文可追溯是优点；不要把摘记说成自动纠错的语义记忆。证据 M1、M2、A1。

### Q15｜预算中的 6000 和 48000 到底是什么？

**面试官：** 中文、英文、emoji 和 JSON 转义怎么计量？

**候选人：** 当前 Memory 预算按完整序列化 JSON 的 Java UTF-16 长度，包含角色、来源、范围、转义和状态元数据，默认 6000。系统提示、当前问题和本轮工具历史不属于这个 Memory 子预算，但 transcript 另有 48000 字符限制。检索证据使用 BGE tokenizer 的预算，也不是生成模型 tokenizer。不能直接把这些数当真实 token、费用或模型余量。

**追问：** 超长一轮会不会让历史完全为空？

**候选人：** 新策略尽量保留真实范围摘录并警告，不能放下来源元数据时也会明确预算不足；可以 memory_read 分段补读，不宣称截取后仍然完整。

**审查：** 有界管理成立；精确生成模型 token 控制没有实现。证据 M1、M2、M3。

### Q16｜turn_id、哈希、checkpoint 为什么同时需要？

**面试官：** 相邻 user/assistant 不就能配成一轮？哈希能防越权吗？

**候选人：** 并发插入可能交错，因此新完成轮共享 turn UUID；旧记录有歧义时不猜配对。checkpoint 是派生原文摘记，记录 owner scope、通过位置、摘记、源哈希及乐观锁版本，加载回查角色、turn、范围、原句和哈希。哈希只发现与当前原文不一致，不是身份认证、签名或事实验证。权限靠项目和会话归属校验，ID 查询还绑定 session。

**追问：** 数据库内容被有权限的人一起改了呢？

**候选人：** 普通 SHA-256 不提供那种防篡改证明；不能夸大为安全签名体系。

**审查：** 轮次和来源治理可讲，真实性要限定为匹配原文。证据 M1、M4、M5。

### Q17｜工具观察压缩和会话摘记有什么区别？

**面试官：** 压缩会不会打断 tool_call_id 配对或丢私有推理字段？

**候选人：** 会话摘记选择已完成公开历史；工具压缩处理本次执行中增长的观察。preview 包装原始前缀，明确可能不是完整原观察；structured 保留状态、策略、警告、引用位置、产物和分页，显式说明省略正文。只压旧轮，最新轮及 assistant 必需协议字段不动；压后单条最多 1000 字符，无法装下必需协议时停止。

**追问：** 1000 字符还能保证所有引用不丢吗？

**候选人：** 不能，引用本身很长也会省略并报告数量。它保留可重读指针，不是完整语义摘要，更不保证无损。

**审查：** 协议保护有实现与回放；不能宣传无损压缩。证据 M3、T2。

### Q18｜81.7% 是什么，hybrid 是否最好？

**面试官：** 分母多少？240 是 240 道题吗？

**候选人：** 20 个人工场景，每题 16 完整轮，dev10/test10；四策略乘三种预算是 240 条条件。81.7% 是 test10、6000 字符时各场景完整重要引句覆盖率的平均值，不是模型准确率。hybrid 全部要求均保留只有 70%；仅两题有旧要求标签，平均暴露 50%。覆盖更多也可能增加旧约束，所以默认配置没有被证明最优。

**追问：** 真实模型回复与费用报告在哪？

**候选人：** 当前工作区未找到真实模型 model-report.json。已有评测 Runner 和本地解析测试，不能用代码存在冒充评测已完成；未来引用恢复成绩也不等于自由回答质量。

**审查：** 可以据实报告诊断，不可用作业务准确率。证据 E1、T3。

### Q19｜共享 RAG 索引共享了什么，坐标是什么？

**面试官：** 不同方法为什么不需要不同数据库？

**候选人：** 方法共享规范化原文与 canonical leaf chunks。MySQL 存完整原文、文字版本、片段顺序与范围；Qdrant 存对应片段向量。Top-K、邻居和 RSE 在查询时组合原文区间，不需要重建更长向量。坐标是规范化文字的 UTF-16 半开区间，不是音频时间或原始文件字节；parent_id 是段落锚点，不是 LLM 语义章节。

**追问：** 已经完整处理文档版本迁移和跨库一致性了吗？

**候选人：** 没有。已存文字哈希和索引版本，保存时做原文匹配校验；这不等于完整版本治理、embedding 迁移或跨存储事务。

**审查：** 共享数据模型成立；版本字段不是版本治理全部。证据 R1、R2、P4。

### Q20｜BM25 是独立召回还是向量结果加分？规模如何？

**面试官：** 用了 Elasticsearch、Lucene 或 Qdrant sparse vector 吗？

**候选人：** 没有。RAG 从有界项目的 MySQL chunks 实时构造轻量 BM25，统计片段词频、片段级 DF 和平均长度，再逐片打分；它不依赖向量候选，所以是独立词法召回。当前最多 1000 文档、10000 片段，超限报错。目录分页只减少给模型的条目，后台仍加载有界完整集合。

**追问：** 十万文档每轮重建能承受吗？

**候选人：** 当前不适合那个规模。需要持久倒排索引、增量更新、分区及真正按候选文档加载；容量 count 判断也不是分布式配额锁。

**审查：** 可说轻量独立召回；不能叫生产级搜索引擎。证据 R1、R2、R3。

### Q21｜把 BM25 和 cosine 直接相加不行吗？手算 RRF

**面试官：** RRF 公式、rank 起点和 k 是什么？

**候选人：** 原分数尺度不同，也不是同一种概率。实现按片段 ID 融合排名，公式是 sum(1/(60+rank+1))，rank 从 0 开始。两路第一名是同一片段时得到 2/61。RRF 本身也不是校准相关性，更不证明事实正确。

**追问：** A 在两路为第1/12名，B为第2/1名，谁高？

**候选人：** 用一基名次，A=1/61+1/72约0.03028，B=1/62+1/61约0.03252，B更高。我没有引入校准 Cross-Encoder 来把排序转成相关概率。

**审查：** 应能现场手算，不能只背“融合提升召回”。证据 R4。

### Q22｜“模型自主选择”是实现入口还是已证明能选对？

**面试官：** 是 if/else，还是模型真的传策略参数？

**候选人：** 原生工具定义暴露检索、证据组合、预算、文档 IDs 和理由，模型可通过 Function Calling 选择，服务器只做允许范围校验与执行；缺省 hybrid/top_k。目录类型是文件来源和格式，不是数学/法律语义分类器；先读目录是提示建议，不是强制规则。mock 测试能证明参数进入执行，不证明模型稳定选择正确。

**追问：** 和固定 hybrid/top_k 相比，真实模型提升多少？

**候选人：** 尚无成对业务评测。当前可说支持策略选择，不能说已经实现最优自适应或准确率提升。

**审查：** 简历“支持模型选择”成立，效果口径须收敛。证据 R1、R7、E2。

### Q23｜RSE 是什么，与邻居扩展、完整 dsRAG 有何区别？

**面试官：** 连续证据段怎么选，效用从哪来？

**候选人：** Top-K按排名装片段；邻居固定扩展±1；RSE排名近似对候选赋 exp(-rank/10)-0.2，未命中为-0.2，贪心选最高总效用连续段，最多6片、最低0.1，不跨文档、不返回重叠段。比如值为0.8、-0.2、0.7的三片，总值1.3，预算允许时可桥接中间负值。没有校准重排器、AutoContext或模型语义分节，不能声称完整实现dsRAG。

**追问：** 相关文档零召回，RSE 能找回来吗？

**候选人：** 不能。邻居可带入未命中的相邻片段，RSE可桥接短间隙，但都需要正效用锚点附近的原文。文档没有锚点或者遗漏很远，扩段不能自动救回。

**审查：** 要能解释 greedy、惩罚、长度和预算，而不是说“RSE就是多取几个chunk”。证据 R5；参考 [dsRAG RSE 源实现](https://github.com/D-Star-AI/dsRAG/blob/main/dsrag/rse.py)。

### Q24｜为什么用384/48？换embedding模型会怎样？

**面试官：** 900字符有什么问题，384是否最优？

**候选人：** 当前编码窗口512包含CLS/SEP，正文最多510。旧900字符可能保存全文，却只把前510词元编码成向量。新切片按未截断token计数，上限384、重叠最多48，优先保留句/段边界；重叠可能更少。参数是保守固定值，没有证明通用最优。检索组合的BGE token计数不能代替生成模型计数。

**追问：** 同维度换模型无需重建，对吗？

**候选人：** 不对，维度相同不代表语义空间相同。目前payload写模型目录名和维度，查询未核验模型哈希或语义版本，collection距离配置也未在代码验证；不能说已经实现模型迁移兼容。

**审查：** 编码截断问题有真实诊断；迁移核验是待补项。证据 R6、E2。

### Q25｜显式降级是否覆盖所有失败与旧资料？

**面试官：** Qdrant挂掉是不是所有查询都能用BM25？

**候选人：** 新版资料的向量分支异常时回退到BM25，返回实际策略和警告；指定文档ID必须属于本项目新版索引。旧资料独立走dense/Top-K，混合新旧时没有统一分数重排，只尝试保留兼容结果位置，仍可能受预算省略。只含旧资料没有新版BM25能力，因此不能保证全部分支都能回退。

**追问：** 401或collection缺失也算网络不可用？选择BM25还会查Qdrant吗？

**候选人：** 当前catch RuntimeException过宽，错误被混标“向量不可用”，需要细分认证、配置、数据与网络故障。未限定新版文档时，BM25选择也会查向量以兼容旧文档；不能绝对说不会访问Qdrant。

**审查：** 显式实际策略可讲，不是完整容灾体系。证据 R1、R7。

### Q26｜1458条实验记录能证明RSE提升吗？

**面试官：** 语料多大，测试独立吗，生产召回率如何？

### Q27｜MySQL、MinIO、Qdrant一致性和Redis恢复能保证什么？

**候选人：** 要看Redis持久化配置；缓存与数据库、文件也有崩溃窗口，不能宣称永久不丢或自动精准续跑。当前清理还用KEYS扫描，只适合小型本机场景，不能沿用到大规模生产。
