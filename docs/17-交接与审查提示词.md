# 交接：音频工作台改动汇总 + 给审查 Agent 的提示词

> 用途：把这份文件交给另一个 agent 做代码审查与优化。第一部分是"改了什么"的客观事实，
> 第二部分是可以直接粘贴给对方的提示词（含仓库、命令、已知风险点与交付要求）。

## 一、这批改动的目的

把"AI 音频工作台"从**生成后只能整篇重来**，改成**一个对话驱动、右侧可看可改的稿纸**：

1. 讲稿在右侧以"黄色稿纸"呈现，可翻页、可直接编辑（离开即保存并只重念这一段）
2. 音频默认只合成第 1 段，其余按需合成（省时省钱，用户先看稿）
3. 所有动作（改一段、整篇换格式、再生成一些、继续合成、换音色、撤回）都由对话里的
   agent 通过工具完成，界面上不再放操作按钮

## 三、关键文件

**后端**（`backend/src/main/java/com/bedouyu/audiorag/`）

- `tools/audio/`：`AudioSegmentsTool` `ReviseSegmentTool` `RewriteScriptTool` `ExtendScriptTool`
  `GenerateAudioTool` `RevoiceSegmentTool` `UndoSegmentTool` `AudioToolTarget`（队列定位：显式 id →
  本项目最新 → 该用户最新，且先校验显式 id 是否合法）
- `service/ContinuousAudioStore.java`：`replaceScripts`（整篇就地替换）、`appendScripts`（追加）、
  `reviseScript`、`previousScript`、`segmentScript`、`fullScript`、`refreshQueueStatus`
- `service/ContinuousAudioService.java`：`rewriteWhole`、`extendWhole`、`reviseSegment`、`refill`、
  `splitInto`（按句切分）、`generate`
- `service/ScriptReviser.java`：`revise`（单段）/`rewriteWhole`（整篇）/`extend`（续写），三套 system prompt
- `service/AudioRetention.java`：被替换的旧音频进 `retired/`，8 小时后清理
- `ai/NativeFunctionCallingGateway.java`：流式调用、输出前断流重试一次、失败原因落日志
- `core/loop/AgentBudget.java` + `agent/audio/AgentOrchestrator.java`：模型/工具轮数预算（40/48，可配）
- `controller/AiController.java`：`/segments/{n}/revise`、`/segments/{n}/undo`、`/rewrite`、`/extend`、`/refill`
- `resources/prompts/audio/supervisor.txt`：主控行为约束（改稿口径、草稿不得替代音频正文、不要按钮化）

**桌面端**（`desktop/src/renderer/src/`）

- `components/ScriptNotebook.vue`：稿纸（分页、编辑、离开即保存）
- `components/AudioPanel.vue`：右侧面板（稿纸 + 音频摘要 + 来源 + 分段详情 + 导出）
- `components/ChatPanel.vue`：对话、思考过程时间线、失败气泡、看门狗
- `composables/useAudioCenter.js`：`refresh` `refill` `revoice` `reviseSegment` `rewriteWhole`
  `extendWhole` `undoRevision`
- `shared/audio-queue-policy.js`：状态文案与 `canRefill` 等策略

## 五、给审查 Agent 的提示词（可直接粘贴）

```text
你是资深 Java / Vue 代码审查者。仓库：D:\desktop\AI\AI音频\audiorag-java（分支 master，已推送）。
这是一个 Spring Boot 4 + Java 17 后端 + Electron/Vue 3 桌面的"AI 音频工作台"。

【背景】近期把它改造成"对话驱动、右侧稿纸"的形态：
- 讲稿在右侧黄色稿纸里分页展示、可直接编辑（失焦/翻页即保存并只重合成这一段）
- 音频默认只合成第 1 段，其余按需生成（refill）
- 所有操作交给对话里的 agent，通过 7 个工具完成：
  audio_segments（读）、revise_segment（改一段）、rewrite_script（整篇重写）、
  extend_script（追加）、generate_audio（继续/全部合成）、revoice_segment（换音色）、
  undo_segment_revision（撤回）
- 界面上不再有操作按钮，只剩翻页与"导出为文件"

【请审查的重点】按严重程度列出问题，每条给出 文件:行号、为什么是问题、建议怎么改：
1. 正确性：整篇重写/追加的段落编号、状态与旧音频清理是否正确；越权与队列定位
   （AudioToolTarget 回退到"用户最近一条"是否可能作用到错误的音频）；
   undo 的"来回切换"语义是否符合用户预期
2. 事务与并发：ContinuousAudioStore 里加锁查询与生成线程的竞争；
   重写/追加与正在合成的片段是否可能互相覆盖；@Version 冲突处理
3. 超时链路：revise/rewrite/extend 三个工具内部要调模型（ScriptReviser 预算 180–240s），
   而工具执行超时是 audiorag.agent.tool-timeout-ms=30000，声明了 hasSideEffects；
   是否存在超时 → AgentStopped → 用户看到 409 但实际改了一半的路径
4. 成本与体验：稿纸"离开即保存"每次都会重新合成（模型 + TTS 双份成本）；
   是否需要"只存文字、稍后合成"的选项
5. 前端状态：ScriptNotebook 的草稿与 useAudioCenter 的 10 秒轮询是否会互相覆盖用户的未保存输入；
   自动保存与翻页的竞态；v-show 隐藏时的轮询开销
6. 代码卫生：AudioPanel.vue 重构后残留的未使用变量/函数（openEditor、editText、
   loadFullScript、revoiceVoice 等）；重复的队列解析逻辑；中文注释是否与实际行为一致
7. 测试缺口：给最该补的 3–5 个测试用例列出名称与断言要点

【约束】
- 只做审查与建议，不直接大改；给出最小可行的修改方案
- 界面文案必须保持中文；不要引入新的操作按钮（产品方向是一个对话完成所有事）
- 不要改动"讲稿必须以 audio_segments 正文为准、草稿不得替代"这条规则
- 提交历史里的 534 后端 / 39 桌面测试必须保持通过

【环境与命令】
- 后端：D:\DevTools\apache-maven-3.9.16\bin\mvn.cmd -Dmaven.repo.local=D:\desktop\AI\AI音频\audiorag-java\.cache\m2 -B clean package -DskipTests
  注意：必须 clean（增量编译会产生与源码不一致的 class），打包后先停掉 java 再 package
- 测试：同上把 clean package 换成 test；桌面：desktop 目录下 npm run build / npm test
- JDK：D:\AI-Toolchain\jdk-17.0.20.1+1
- 启动后端：java -Dfile.encoding=UTF-8 -Djava.net.useSystemProxies=false -jar target\audiorag-backend.jar
  （端口 18081，健康检查 /api/health；CosyVoice 在 50000；MySQL/Redis/Qdrant/MinIO 用 docker/ai-services.yml）
- 关键文件见 docs/17-交接与审查提示词.md 第三节

【交付格式】
1. 问题清单表：严重度 | 文件:行 | 问题 | 建议
2. 3–5 个最该补的测试
3. 一段"如果只做三件事，做哪三件"的结论
```

## 六、已知遗留（供审查者参考，不必重复发现）

- 稿纸自动保存每次都触发重新合成（成本/延迟）
- 整篇重写的段数按句子边界重排，页数可能与原来不同
- 断流只重试一次，没有指数退避
- `AudioPanel.vue` 里重构后仍留着几个不再被模板引用的函数与 ref
- 讲稿检索只按"项目最新一条 / 用户最新一条"兜底，多队列场景可能选错
