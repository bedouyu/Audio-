# DeepSeek 真实接口测试记录

测试日期：2026-10-21，北京时间。使用项目当前私有配置中的 DeepSeek 服务，实际请求的模型别名为 `deepseek-chat`；未用模拟回答或本地模板代替真实生成。语音使用本机 CosyVoice 3、RTX 4060 和官方示例音色。

## 测试范围与结果

通过运行中的项目 API 创建独立测试账号，并执行自然语言请求、后台准备、分段合成、音频下载、历史恢复、幂等回执和进度保存。测试数据与原有用户内容分开；未修改原有用户正文和收听进度。

前三类音频使用同一自然语言入口，无需指定内容模块。约一分钟案例的音频时长验收上限为 90 秒，这是本轮测试容差，并非精确时长承诺。检查了 WAV 格式、24 kHz 单声道 PCM16、样本非静音与完整下载；未进行自动语音识别回读或完整人工听音评价。

接口检查包括：登录、未登录访问拒绝、无效请求编号和超长时长拒绝、真实音色清单；已完成音频的历史查询、记录保存、倍速和进度读写；同一请求编号与同一正文返回原队列和音频编号，正文不同则返回冲突。服务重启后，中文与双语音频仍为完成状态、音频编号未变，收听进度及倍速保留；Agent 草稿与待确认状态保留。测试账号访问既有其他用户队列被拒绝。

## 发现与修复

1. **段落中的空行导致英语合成异常。** 复现到本机文本规范化组件对连续换行与 CRLF 的断言失败。送入 CosyVoice 前统一空白，数据库保存的原始正文保持原样；添加段落、CRLF 和混合空白用例。原有失败队列已完成 9/9 段，不再重复生成。
2. **否定语言指令被误读。** “中文故事，不要英语”应保留中文；英文故事中的局部中文讲解应识别为双语。缩小否定语境的作用范围，避免“不用检索用英语”等表达吞掉后续语言要求。
3. **新闻时间范围不准确。** “上周”改为上一完整自然周；“最近 N 天”按明确天数计算并验证范围，不能静默套用七天默认值。
4. **制作要求污染新闻查询。** 移除查询中的“用中文做成一分钟简报”等制作指令和重复时间提示；适当分隔中文类别词，保留国际、地区和具体主题要求。真实检索恢复为当前时间范围内的带日期来源，未放宽为旧新闻或国内替代查询。
5. **生成成功但内容验收失败。** 第一份可播放新闻长达 128.96 秒，并使用国内 C919 航班补足国际时政条数，判定为质量不通过。补充中文、英文和双语共用的正文长度预算，要求开场及来源说明计入总量；新闻必须按实质匹配主题，证据不足时明确不足，禁止无关报道凑数。没有硬截断正文或加速音频掩盖长度问题。

新闻尝试记录：

- 首次检索因查询过度约束，没有取得时间范围内的可用来源，在正文生成和语音合成前失败。
- 查询修复后完成检索和合成，但人工读稿及音频时长验收失败。该次正文、WAV、队列和质量复核保存在结果目录的 `news-before-prompt-fix/`。
- 时长与相关性约束修复后，使用新请求编号执行最后一轮复测，完成真实 DeepSeek 生成与 CosyVoice 合成，耗时 69.95 秒，音频为 84.40 秒。正文将事实、评论和检索限制分开，没有再用国内航班填充国际新闻。

最终新闻仍有明确不足：正文只播报一条会见国际金融咨询委员的消息，自报严格相关事件不足；这不等于已经证明六条候选来源中不存在第二条相关事件。正文共 350 个汉字，超过规划的 180—240 字；实际音频虽在本轮 90 秒容差内，仍长于请求的约一分钟。因此机器报告标为 `passed_with_limitations`，不把“两条新闻、精确时长”宣称为完全通过。

失败记录保留，不以重复提交同一个失败请求来掩盖结果；同一请求编号仍遵循原有幂等规则。
